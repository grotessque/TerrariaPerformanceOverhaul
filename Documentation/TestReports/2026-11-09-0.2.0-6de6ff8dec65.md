## Findings

1. **Run-to-run variability is very low** (p95 spread 0.2 %), so the setup is repeatable.
2. **Frame time is limited by vsync at 60 Hz.** Mean frame time equals the refresh period, and about half of all frames are
   just above 16.67 ms because of present timing jitter. These numbers show vsync pacing, not how much work a frame takes.
   Optimizations will not be visible in frame_ms while vsync caps the rate. → 0.3.0 adds CPU-side metrics that do
   not depend on vsync (draw CPU time, world update time with a per-category split).
3. **`frames_over_16_7ms` is not meaningful with vsync** (≈ 50 % of frames by jitter alone). → replaced in schema 2.
4. **The overlay is expensive:** +88 µs CPU per frame and +3.1 MB/s allocations (+51 % process allocation rate,
   +50 % gen0 collections, ~2× GC pause). Cause: `Utils.DrawBorderString` → `ChatManager.DrawColorCodedStringWithShadow`
   parses the text as chat markup every frame and draws it several times for the border (verified from IL).
   → 0.3.0 draws the overlay with `DynamicSpriteFont` `DrawString` directly (no parsing, 2 passes). Must be re-measured.
5. **Diagnostics overhead without overlay: 2.6 µs/frame** self-measured (0.016 % of a 16.7 ms frame). The external
   check (PresentMon/CapFrameX, BenchmarkProtocol.md §4) has not been done yet.
6. **`gpu_adapter` showed the monitor name (`LC27G5xT`)**, not the GPU: FNA's adapter description is the display device
   name on this system. → renamed to `display_device`; `gpu_name`/`cpu_name` are read from the Windows registry in 0.3.0.
7. Vanilla baseline with TPO idle: the game allocates ~6 MB/s and runs ~22 gen0 collections per minute at spawn.
   This is a reference value for later comparisons, not a problem in itself.
