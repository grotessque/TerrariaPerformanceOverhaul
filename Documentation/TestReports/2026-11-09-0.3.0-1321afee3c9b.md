## Findings

1. **Overlay fix confirmed.** Self time 91 → 29.5 µs/frame (−68 %). Overlay-induced allocation **+3.1 MB/s → 0**
   (6.04 MB/s with and without overlay), gen0 33 → 22, GC pause 10.5 → 7 ms per 60 s.
2. **Self-measurement cross-checked.** Overlay adds +27 µs self time and +0.03 ms (≈ 30 µs) to `draw_cpu_ms_mean`:
   two independent measurements agree.
3. **The scene is very light for the CPU.** Draw ≈ 1.0 ms + update ≈ 0.17 ms of a 16.7 ms frame (≈ 7 %). With TPO only,
   there is no CPU bottleneck to optimize in this scenario; frame time is set by vsync.
4. **Draw cost has a 4-frame cycle.** Exactly every 4th frame takes ~2.1 ms vs ~0.69 ms (25 % of frames; run 191719).
   `Main.DoDraw` branches on `Main.renderCount == 3 / 2 / 1` (verified from IL), so part of the render-target work
   runs on a 4-phase cycle. Which phase is the heavy one was not determined. This explains p50 0.8 ms vs p95 2.2 ms.
5. **Run-to-run variability of CPU metrics is larger than of frame time:** draw mean ±1.6 %, update mean ±3.3 %
   (3.3 % / 6.6 % min–max spread). With 3 runs, differences below ~5 % (draw) / ~7 % (update) are not detectable.
6. **Working set differs between game sessions** (1.24 GB in the 0.2.0 session, 0.95 GB here, 1.00 GB in the separate
   novsync session) with the same mods and scene. Compare memory only within one session, or across many sessions.
