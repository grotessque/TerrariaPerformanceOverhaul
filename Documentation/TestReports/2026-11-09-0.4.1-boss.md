## Findings

1. **These bosses do not stress the CPU on this machine.** Worst case draw p99 3.3 ms + update p99 1.1 ms ≈ 4.4 ms of a
   16.7 ms frame; no frame over 25 ms. There is still no frame-time problem to optimize.
2. **With Calamity, the same boss costs more, but not only because of Calamity's code:** the scene differs.
   Eye of Cthulhu with Calamity had 18 active NPCs at the end vs 7 without (more Servants of Cthulhu), so
   "same boss" is not the same load. NPC update ×2.2 includes these extra NPCs.
3. **Player update stays the largest Calamity cost** (+0.20 ms per update, ×3.9), the same as in the idle scene.
   It does not depend on the boss.
4. **Calamity allocates 13–13.6 MB/s in boss fights** (×2.4–2.5 vs vanilla) → ~0.8 gen0 collections per second,
   ~16 ms GC pause per minute. Individual pauses are short (≈ 0.35 ms on average); no hitches were recorded.
5. **No boss produced projectiles at the sampled moments** (0 at start and end). These early bosses do not test
   projectile load.

## Hypothesis to verify: residual cost after unloading Calamity

World update time outside the measured entity phases ("outside"), vanilla runs only:

| Runs | Position in launch | Settings | outside, ms/update |
|---|---|---|---|
| 0.3.0 spawn-idle ×7 | first mod set of the launch | 1080p, frame skip Off, day | 0.025–0.027 |
| 0.4.1 boss-eoc | first mod set of the launch | 1440p, Subtle, midnight | 0.023 |
| 0.3.0 spawn-idle ×3 (Calamity session) | **after unloading Calamity** | 1440p, Subtle, day | **0.104–0.106** |

The after-unload runs show about 4× more work outside the entity phases. Together with the memory that stays high
after unloading, this suggests that unloading Calamity leaves something running. **Not confirmed:** the groups also
differ in time of day and (for the 0.3.0 group) resolution and frame skip. Test to confirm or reject: one launch,
fixed settings, `spawn-idle` ×3 with TPO only → enable Calamity → disable Calamity → `spawn-idle` ×3 again.
